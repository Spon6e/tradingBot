# Market Analysis Bot

Русскоязычный Telegram-бот для технического анализа криптовалют и акций в USD.
Строит сценарии роста, падения или нейтрального рынка, отправляет свечной график
и ведёт отдельную виртуальную сделку номиналом **$100** на каждый принятый сигнал.

## Возможности

- EMA 20/50, RSI 14, ATR 14, объяснение сигнала и сравнение объёма со средним.
- Криптовалюты: пары Binance к USDT/USDC; интервалы 15m, 1h, 4h, 1d.
- Акции в USD: Yahoo Finance через yfinance; интервалы 1h, 1d.
- Графики PNG с ориентиром входа, целью и стопом.
- Персональная статистика, журнал, CSV-экспорт и уведомления о закрытии.
- Сохранение позиций, комиссии, срока, списка наблюдения и очереди уведомлений в SQLite.
- Защита от повторной сделки по одной свече; одна активная позиция на тикер/интервал для пользователя.
- Автоматическое наблюдение до 10 тикеров на пользователя (100 на экземпляр бота).
- Историческое тестирование с входом на следующей свече.
- Приватный доступ по Telegram ID, работа только в личных чатах.

Бот не размещает реальные ордера и не требует ключей от биржи или брокера.
Модель эвристическая: балл от −3 до +3 не является вероятностью успеха.
Доходность стратегии заранее не подтверждена.

## Быстрый запуск в Windows

Установите Python 3.12 или новее, распакуйте проект в нужную папку и откройте в ней PowerShell:

~~~powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -c constraints.txt .
Copy-Item .env.example .env
notepad .env
~~~

Вставьте в .env токен от [@BotFather](https://t.me/BotFather). Затем:

~~~powershell
.\.venv\Scripts\python.exe -m market_bot --check
.\.venv\Scripts\python.exe -m market_bot
~~~

Откройте личный чат с ботом и отправьте /id. Впишите полученный ID в
TELEGRAM_ALLOWED_USER_IDS, остановите процесс сочетанием Ctrl+C и запустите его снова.
При пустом списке ID и ALLOW_PUBLIC_ACCESS=false анализ недоступен, /id продолжает работать.

## Linux / macOS

~~~sh
python3 -m venv .venv
.venv/bin/python -m pip install -c constraints.txt .
cp .env.example .env
# Отредактируйте .env
.venv/bin/python -m market_bot --check
.venv/bin/python -m market_bot
~~~

После установки доступна также команда market-analysis-bot внутри виртуального окружения.
Файл .env автоматически загружается из текущей папки; существующие переменные окружения
имеют приоритет. Другой файл: python -m market_bot --env-file /path/to/.env.
После изменения исходников переустановите пакет; для разработки используйте pip install -e ".[dev]".

## Команды

- /start, /help — инструкция.
- /id — собственный Telegram ID.
- /analyze BTCUSDT 1h — анализ криптовалюты.
- /analyze AAPL 1d — анализ акции.
- /scan — BTCUSDT, ETHUSDT, AAPL и MSFT с виртуальными заявками при наличии сигналов.
- /watch BTCUSDT 1h — автоматические прогнозы; проверка каждые 5 минут.
- /unwatch BTCUSDT 1h — выключить наблюдение; открытые сделки продолжают учитываться.
- /watchlist — список наблюдения.
- /positions — открытые сделки и заявки, ожидающие входа.
- /history — последние 20 закрытых сделок.
- /stats — число сделок, доля прибыльных, чистый результат, средняя доходность, коэффициент прибыли.
- /export — персональная история в CSV (UTF-8 с BOM).
- /backtest BTCUSDT 1h — проверка на доступной истории, до 999 свечей.
- /status — время последней проверки и ошибки обновления ваших позиций.

Для криптовалют интервал по умолчанию 1h, для акций 1d.
Между запросами анализа одного пользователя действует пауза 10 секунд.

## Как считается виртуальный результат

1. Прогноз использует только завершённые свечи.
2. В момент запроса сохраняется виртуальная заявка. Вход — по цене открытия первой
   свечи, которая началась не раньше запроса. Исполнение отражается после завершения этой свечи.
   Поэтому заявка на дневном интервале может ожидать следующего торгового дня.
3. Количество актива = $100 / цена фактического входа. Процентные расстояния до цели
   и стопа переносятся с опорной цены на фактическую цену входа.
4. Цель находится примерно в 2 ATR, стоп — в 1 ATR от опорной цены. На очень дешёвых
   или волатильных активах уровни ограничиваются положительной ценой.
5. Для роста: результат = (выход − вход) × количество. Для падения знак обратный.
   Комиссия вычитается из номинала входа и фактического номинала выхода.
6. Если свеча затронула и стоп, и цель, выбирается стоп. Если цена открытия уже прошла
   стоп, выход считается по цене открытия; при разрыве через цель используется цена цели.
7. По истечении срока позиция закрывается по открытию первой свечи, начавшейся после
   срока. Во время закрытой биржи ждём следующую торговую свечу.
8. Каждый прогноз получает независимые $100; это не общий депозит и не сложный процент.
   Нейтральный сценарий сделку не создаёт.

Позиции проверяются раз в REFRESH_INTERVAL_SECONDS, но результат становится известен
только после завершения выбранной свечи. Уже завершённые свечи обрабатываются по порядку,
включая пропущенные во время краткого простоя. Хранятся контрольные точки обработки.

Доля успешных считается среди закрытых сделок после комиссий. Ожидающие входа не входят
в этот показатель. Коэффициент прибыли отображается как н/д, если убыточных сделок ещё нет.

## Настройки

Все настройки описаны в .env.example. Номинал каждой позиции фиксирован: $100.

- TELEGRAM_BOT_TOKEN — обязательный секретный токен.
- TELEGRAM_ALLOWED_USER_IDS — числовые ID через запятую.
- ALLOW_PUBLIC_ACCESS — false по умолчанию; true явно открывает доступ всем пользователям.
- MARKET_BOT_DB — путь к базе, по умолчанию data/market_bot.sqlite3.
- REFRESH_INTERVAL_SECONDS — период обновления, 15–3600 секунд, по умолчанию 60.
- PAPER_COMMISSION_RATE — комиссия за сторону, по умолчанию 0.001 (0,1%).
- PAPER_TIMEOUT_HOURS — срок после входа, 1–168 часов, по умолчанию 72.

Комиссия и срок сохраняются в каждой позиции: новые настройки применяются к новым сделкам.
Уведомления о закрытии сохраняются в базе и повторяются после временного сбоя.
При аварии между отправкой и записью подтверждения возможно повторное уведомление.

## Историческое тестирование без Telegram

~~~sh
python -m market_bot --backtest BTCUSDT --timeframe 1h
~~~

Используются последние доступные завершённые свечи, максимум 999. Вход — на следующей
свече, одна позиция одновременно, $100 на сделку, комиссия 0,1% за сторону и срок 72 часа.
Последняя незакрытая позиция принудительно закрывается по последней цене выборки.
Просадка считается по закрытым сделкам в долларах, без переоценки внутри открытой позиции.
Тест через Telegram использует текущую комиссию и срок из настроек.
Это короткий технический тест, а не доказательство прибыльности.

## Docker и круглосуточная работа

~~~sh
docker compose up -d --build
docker compose logs -f --tail=100
docker compose down
~~~

Сначала заполните .env. База хранится в постоянном томе market-data; не удаляйте том,
если хотите сохранить историю. Для резервной копии остановите приложение и скопируйте SQLite.
Запускайте один экземпляр бота на один токен и одну базу.
GitHub хранит код; постоянный запуск выполняется на вашем компьютере или сервере.
Docker-конфигурация поставляется отдельно; её необходимо проверить на целевом Docker-хосте.

## Разработка и проверки

~~~sh
python -m pip install -c constraints.txt -e ".[dev]"
python -m ruff check src tests tools
python -m unittest discover -s tests -v
python -m build
python tools/package_release.py
~~~

constraints.txt фиксирует проверенные версии прямых зависимостей; это не полный
межплатформенный lockfile. На GitHub предусмотрены проверки Linux/Windows на Python 3.12/3.13.
Обычные тесты используют фиктивные свечи и Telegram-сессию: токен и доступ к рынку не нужны.

## Ограничения данных и модели

- Binance и Yahoo могут быть недоступны в вашей сети, задерживать или ограничивать запросы.
  Источник Yahoo неофициальный; данные предназначены для личного исследовательского использования.
- Поддерживаются только указанные криптопары и акции с котировками в USD. MOEX и пересчёт валют не реализованы.
- Для акций используются обычные цены без моделирования дивидендов, сплитов, стоимости займа
  для коротких позиций и проскальзывания. Эти события могут искажать сравнение результатов.
- Дневная свеча акции считается завершённой после окончания её локального календарного дня;
  часовая — через час от её начала. Полная биржевая календарная модель не реализована.
- Это учёт по свечам: точная последовательность внутрисвечных касаний неизвестна.
- Если простои превышают доступное окно истории, автоматический результат не выдумывается:
  ошибка отображается в /status; потребуется восстановить данные до продолжения учёта.
- При переходе со старой версии база расширяется без удаления прежних записей.
  Старые позиции без владельца остаются в базе с owner_chat_id=0 и не рассылаются пользователям.
- Автоматическая торговля, новости, обучение ML и обещания точности в проект не входят.
